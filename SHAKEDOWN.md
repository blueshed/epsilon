# Shakedown review — epsilon 0.8.0

_15 agents, 7 dimensions, each adversarially verified. 32 findings survived, 24 were killed._

## The verdict

Yes, but a targeted one — not a rewrite. The architecture is sound (the op/signal seam, the wire, the SQL boundary all hold up under adversarial reading), but the runtime went 1,650 → 3,717 lines across six releases while the README kept saying "~1.7k", and nobody was measuring against the four taxes. There is roughly 190 lines of genuinely dead or duplicated weight, one real availability bug shipping in production, and three public numbers that are false — that is a shakedown, not a crisis.

## What is genuinely good

- **The op channel actually is one vocabulary.** `Signal.apply` unwinds a failed batch atomically (`signal.ts:176-196`) and `RemoteDoc` overrides exactly one method to become remote (`doc.ts:458-461`). "One Signal class both sides" is not marketing — the Lens only ever calls `root.apply()`, so location transparency falls out instead of being maintained.
- **`list()`'s reconcile is the right shape.** `ui.ts:150-156` diffs key sets and lets surviving rows update through their own lenses. That is the hard-won lesson from railroad, kept, and it is why a root snapshot is cheap enough to be the only recovery primitive.
- **The forward-only migration ledger hashes the file, not the meaning** (`migrate.ts:92-101`), and the error text says exactly what to do. That is the correct paranoia for schema. (See below for where it is applied to the wrong file type.)
- **The relational tier's `doc_open` composition-at-open, never-per-write** (`pg.ts:115-119`) is the load-bearing idea of the whole storage design, and the comment there says so plainly. `rel.test.ts` proves restart-hydrate and two-process convergence for real.

## The shakedown, ranked

**1. The doc-native JSONB tier has zero consumers and drags `persist`/`muted` into `doc.ts`.** `pg.ts:122-157` is a whole second implementation of `pgDoc` — promise chain, guarded UPDATE, `doc_ops` insert, `pg_notify`. Every application call site passes `apply` and takes the relational branch: `server.ts:91`, `server.ts:109`, `japan/server.ts:174`, `japan/server.ts:244`. The only callers of the dead branch are `pg.test.ts`'s `blob:*` fixtures. Its cost is not local — `DocOpts.persist` (`doc.ts:55`) is the sole reader of `entry.muted` (`doc.ts:241`, the only read; set at 249/251/259/261), the trickiest invariant in the host. Delete the branch, make `apply` required, and `persist`/`muted`/its comment block at `doc.ts:156-158` go with it. **~-48 runtime lines.** **The pg and taxes dimensions found this independently — the single strongest agreement in the review.** Re-home `pg.test.ts:150-190` (the only tests of the poll death-detector) onto `board:1` rather than deleting them.

**2. Three documents state the size that justifies vendoring, and all three are 2.25x wrong.** `README.md:11`, `package.json:6` and `.claude/skills/epsilon/SKILL.md:3` all say "~1.7k lines". `wc -l` over the 13 non-test files gives **3,717**. It was true at v0.2.0 and was never revised; `DESIGN.md:498` budgets JSX against "past 4k", so the repo contradicts itself inside one release. `japan/package.json:6` carries the false string into a deployed app. **Three dimensions — wire, pg and taxes — flagged this separately.** Fix the three strings; skip the CI LOC gate (it becomes a number people bump). **0 LOC.**

**3. Forward-only is applied to `CREATE OR REPLACE FUNCTION`, which is idempotent by construction.** `migrate.ts:96-101` hash-locks every file in `db/`, including files with zero DDL — `db/003-doc-kit.sql` is 245 lines of nothing but function bodies. In the one deployed consumer this is not theoretical: `trip_apply` is defined **ten times** across `japan/db/010,014,015,016,017,021,022,023,024,026`, and function bodies are 4,262 of japan's 5,418 `db/` lines. It has already caused a bug — `japan/CLAUDE.md:80-84` records that `db/025` copied `mine_open`'s body from `004` instead of the widened `009` and "silently un-shared every board". Add `db/fn/*.sql`: unnumbered, not hash-recorded, re-applied wholesale after the numbered pass. `migrationFiles`' regex (`migrate.ts:54`) already ignores a subdirectory. **+14 in migrate.ts; ~-3,000 in japan.** Do *not* split the existing numbered files — that changes their hashes and throws on next boot.

**4. The ops frame has no correlation id, so neither errors nor minted ids can come home.** `ClientMsg`'s `{action:"ops"}` (`doc.ts:39`) carries no id where `{action:"call"}` beside it does. Consequence one: write rejections (`doc.ts:398`) use the same `{doc,error}` shape as subscription refusals (`doc.ts:342,349,353,364,368`), so the client demuxes by guessing (`doc.ts:625-628`) and japan classifies by regexing English — `japan/index.ts:137-165`, ending in the comment *"Everything else … is a refused WRITE."* Consequence two: `apply()` returns void, so japan hand-rolls a 21-line `onEcho` with a 10-second timeout that matches minted rows **by value** (`japan/index.ts:2298-2318`, called at 1248 and 2340) — two users typing "Kyoto" in the same second pins the wrong row. **The wire and consumers dimensions found the two halves of one hole.** Third witness: epsilon's own CLI does the same guess (`cli.ts:164-170`, "the first ops after my apply are mine"). Cheap fix now: add `write: true` to `doc.ts:398` and gate `refuse()` on its absence (**+4**). Real fix: `doc.write(ops): Promise<Op[]>` on `DocHandle` only — not on `OpSignal`, since `Lens.apply` returns void by delegation (`signal.ts:268-270`) and threading it would break the one-write-path invariant.

**5. `pgAuth`'s throttle is keyed on `ws.remoteAddress` — a shared budget for the whole deployment.** `pg.ts:632`: `const key = String(ws?.remoteAddress ?? "?")`. Behind any PaaS edge — which `README.md:41-55` recommends — that is the load balancer, so the defaults at `pg.ts:629-630` give **all users combined** ten login attempts a minute. `pg.ts:637`'s overflow `attempts.clear()` wipes every counter at once. japan ships this verbatim with 8 users. Don't move it to SQL (`login()` burns bcrypt on unknown emails on purpose). Put `{n, resetAt}` on `ws.data` and delete the `Map`, the overflow clear, and the whole per-process question. **~-12 lines, strictly less state.**

**6. LISTEN mode never learns about a doc that died while its connection was down.** `doc_drop` deletes the op log (`db/005-gone.sql:15`), and the entire reconnect recovery is `for (const name of host.names()) await catchUp(...)` + `refreshViews` (`pg.ts:508-512`) — `catchUp` reads `doc_ops`, finds nothing, reports success. The poll path has the death-detector the listen path lacks (`pg.ts:588-591`, tested at `pg.test.ts:170-190`); there is no listen-mode equivalent. Sibling processes keep rendering a deleted board. `DESIGN.md:330` claims the doorbell covers this; it is silently conditional on the doorbell being heard. Hoist `known` out of the poll fallback and diff it on reconnect. **+8, not a rewrite** — do not merge the two delivery loops, they have different obligations.

**7. Four exported symbols pay no tax.** `applyOps` (`op.ts:110-118`) — exported at `index.ts:3`, zero call sites anywhere, and a verbatim duplicate of the unwind loop at `signal.ts:177-194`. `untrack` (`signal.ts:398-409`) — zero call sites including tests. `batch` (`signal.ts:411-435`) — one call site, `signal.test.ts:78`, paying for two module globals (`signal.ts:36-37`) and a branch in `notify()`, the hottest path. `migrationStatus` (`migrate.ts:133`) — only `migrate.test.ts:97`. **~-70.** Delete `batch` on the honest ground that `apply(ops[])` already batches the only channel an app writes through — *not* on the claim that the flush scheduler makes it redundant, which is false (`signal.ts:50-58` only folds into an *active* flush).

**8. Box the signal's value: root ops stop being a special case.** `Signal.apply` hand-rolls a second atomic applier with its own undo stack (`signal.ts:176-196`) purely because the value is not reachable by a path; `applyOp` carries a 6-line guard refusing root ops for the same reason (`op.ts:71-76`). A `private box: {v: T}` plus a `rootKey` param makes `""` just another key. Verified in a scratch copy: **-12 LOC, 94 tests pass, `tsc --noEmit` clean, no test file touched.** You buy one unwind loop instead of two, one path parse per op instead of two, and `applyOps` stops being dead — which repairs item 7's prose for free.

**9. `doc_open` answers two questions with one signature and the runtime never uses both.** `pg.ts:106` asks *with* a user and keeps only `IS NOT NULL` — a permit. `pg.ts:117` asks *without* and keeps the value — a composition. The scoped composition every doc type must write is computed and thrown away on every open (for a japan trip: a full recompose, discarded). That forces the NULL-user convention, restated at `001-epsilon.sql:34-37`, `003-doc-kit.sql:169-172`, `100-board.sql:97/125`, `101-tally.sql:5-6`, `pg.ts:57-58/72-77`, `law.ts:41-42` — and it cost japan a whole migration, `db/025-compose-as-the-host.sql`, 110 lines to flip a NULL test in three functions. Split it: `doc_may(doc, user) → boolean`, `<t>_open(doc) → jsonb`. The convention becomes unrepresentable. **LOC-neutral in core; it must subsume the `guard` closure (`pg.ts:72-77`), not sit beside it, or you trade one convention for three permit paths.**

**10. The remaining tidy.** `popDisposeScope`'s disposer strands every disposer behind a thrower (`signal.ts:322`) while `drain()` two hundred lines up takes real trouble to isolate errors (`signal.ts:78-85`) — one policy, not two (**+5**). The hash refcount (`route.ts:71-94`) is 20 lines of armor whose `hashSignal = null` at `route.ts:92` is a latent bug: computeds already returned by `route()` close over the dead signal and silently stop updating (**-20**). `RouteHandler`'s bare `Promise<Node>` form is documented as broken in the stack's own terms at `route.ts:32-37` — narrow to `Node | Promise<() => Node>` (**-15**). `OpsHandler`'s `undefined` arm (`signal.ts:32`) is unreachable — `notify` has one call site, `signal.ts:195`, inside `apply(ops: Op[])` — yet `DESIGN.md:11` sells it (**-5**). `op.ts` is the only source file with no test beside it, against `README:86`'s "the tests are the contract"; ~25 lines pins the escape round-trip and the `~1`-before-`~0` order (`op.ts:34/45`) and the FORBIDDEN negative case (`op.ts:24`). And `epsilon/index.ts:115` — the reference demo — rewrites `boardName.textContent` from the doc **root** on every op, so anyone's card add clobbers your caret mid-rename. One `document.activeElement` guard.

## The one radical move

**`db/fn/` — stop treating a function body as a migration.** The forward-only ledger exists because DDL is not replayable. `CREATE OR REPLACE FUNCTION` *is* replayable; that is what `OR REPLACE` means. Applying one rule to both is the single most expensive mistake in the stack, and it is measurable: 79% of japan's `db/` is function bodies, `trip_apply` exists ten times totalling 2,948 lines to express one 449-line function, and the ritual has already produced a silent data-visibility bug that only `pglite.test.ts` caught. `db/101-tally.sql`'s own header admits it — "there is nothing here to migrate later". The fix deletes a concept rather than adding a mechanism: numbered files keep doing the thing only they can do (tables, columns, indexes, seeds), and the vocabulary becomes a file you edit in place. It costs `migrate.ts` about fourteen lines. Because `upgrade.ts:23-25` excludes `db/` from SCOPE, it reaches only new scaffolds — so the migration cost you would normally fear does not exist. Do this one first.

## What to leave alone

- **"0.8.0 has zero adoption" — false, and the reviewers missed it.** `japan/alt.ts` (623 lines, served at `server.ts:296`, with its own `alt.test.ts`) imports and uses `mount`, `routes`, `route` and `navigate` (`alt.ts:15-17, 214, 561`). The router earned its 354 lines. Only `when()` (`ui.ts:202`) has no consumer anywhere — watch it, don't cut it yet.
- **Narrowing `Lens.get()` to track by prefix.** Adds ~20 to delete 9, and it wouldn't help: japan's per-row effects read doc-wide `computed()`s that return fresh objects (`japan/index.ts:191`, `:277`), so they re-fire on every op regardless. An `equals` on those two computeds is the real win, and it is app-side.
- **A `field()` primitive.** Sixth primitive in a file whose header says five, and it encodes app policy (revert-on-empty vs accept-empty vs commit-on-change) that differs across japan's five sites. Fix the demo's guard; document the pattern.
- **Deleting `route.ts`'s thunk form, `onError`, and the runId guard.** `SKILL.md:42` documents `await board.ready`, which rejects on refusal — a permission-gated handler legitimately awaits. Narrow the bare-Promise form only.
- **Making `pgAuth` non-async.** An async signature is the stable one; narrowing it is a public-surface change across twelve call sites for zero behaviour.
- **Replacing `doc.v === 0` with `remote.reopen()` (part b).** Silently breaks `japan/index.ts:2769` with no compile error, against `DESIGN.md:486`'s own contract. Take the one-line `doc.state !== "open"` and stop.
- **Exporting `escapeToken`.** No consumer has ever built a keyed pointer by hand — `japan/index.ts` has zero `.at(` calls. Add it when someone asks.
- **Per-file LOC counts in the README table.** Twelve more numbers that go stale exactly the way "~1.7k" did. Add the two missing rows (`passkey.ts` — 343 lines, 4th largest, and the most security-sensitive file — and `index.ts`) and leave the counts out.
